# Magpie Digital Pet：完整养成版设计

日期：2026-10-30  
状态：已确认，可进入实施  
选定路线：路线 1「完整养成版」  
已拍板：养成状态跟随每只搭档保存；本轮新增操作页面优先，CLI 只保留原有命令并增加只读状态摘要。

## 1. 意图与原因

当前插件已经能把 Magpie 网关请求稳定喂给数码搭档，并保留了上游 650 只图鉴与进化数据，但主页实际呈现为「名称 + 进度条 + 统计 + 流水」，用户看不到宠物本体，也缺少主动操作、状态反馈和短期目标。本次改造的目标不是重写上游进化引擎，而是在它外面补一个清晰、轻量、可长期使用的本地养成层，让插件既能随网关使用自动成长，也能在碎片时间主动照顾宠物。

## 2. 已确认基线

- 项目：`E:\LLM_Config\Magpie\plugins\magpie-digital-pet`。
- 当前插件版本：0.3.0，移植自 `@jcendal/opencode-digital-pet` 0.18.0。
- 当前真实存档：第 1 代 Digiegg，11.33%，已喂 165 个请求、566.3K tokens。
- 离线自检基线：25/26 通过；失败项出现在「服务关闭后请求」断言。进一步复现显示服务本身已在 1ms 内关闭，但当前 shell 配置了 `HTTP_PROXY=127.0.0.1:47316` 且没有 `NO_PROXY`，Bun `fetch` 对 localhost 也走代理，关闭后收到代理的 HTTP 502，测试把“请求仍得到响应”误判为“服务仍在线”。
- 实际页面无脚本错误，但没有展示宠物像素形象，也没有照顾、心情、清洁、探险或目标系统。
- 上游包内存在 12 类像素姿态（进食、开心、生气、受伤、睡觉、行走等）以及照顾/探险相关实现；当前 Magpie 页面未接入。已验证本机上游包可提取 646 个 sprite、7227 帧像素数据，剩余图鉴项需要稳定兜底。
- 设置页写的数据库路径与 README、实际代码不一致。
- 项目原本没有 Git 仓库；已建立基线提交 `95fdd44`，后续所有改动都可回退。

## 3. 目标

1. 保留现有 token 自动喂养、650 只图鉴、世代、冻结、钉 ID、SQLite 存档和 CLI。
2. 主页首先展示一个会动、有状态、有反馈的宠物主场景，而不是统计表。
3. 增加低压力的养成系统：饱食、心情、精力、清洁、亲密。
4. 增加主动操作：喂食点心、玩耍、清洁、休息、摸蛋。
5. 增加轻量探险：派出宠物巡逻，结束后获得碎片、亲密和随机见闻。
6. 增加每日小目标与本地成就，提供几分钟内可完成的循环。
7. 改进图鉴与历代伙伴展示，让收集进度可见。
8. 修复已复现的服务关闭问题、文档路径错误和页面输出安全问题。
9. 支持 Magpie 当前浅色/深色主题，窄窗口也可操作。
10. 所有新数据仍保存在插件本地 SQLite，不要求联网、账号或云服务。

## 4. 非目标与反目标

- 不修改网关请求，不解析 Agent 上下文，不注入提示词，不增加 LLM 调用。
- 不做账号、云存档、排行榜、付费或联网社交。
- 不做宠物死亡、强制打卡或惩罚性机制；离线很久只会轻微降低状态，不让用户产生负担。
- 不改变上游进化阈值、进化路线、图鉴 ID 或既有 usage receipt 语义。
- 不承诺为 650 只宠物逐只手工绘制新图；优先复用上游内嵌像素帧，并为缺失帧提供稳定的程序化兜底。
- 不顺手重写 Magpie 宿主或 CLI。

## 5. 已考虑的方案

### 方案 A：完整养成版（已选）

在现有引擎外新增本地照顾、探险、目标、成就和视觉层。优点是玩法提升明显、可维护边界清楚；代价是需要新增表、规则测试和较多 UI 工作。

### 方案 B：快速打磨版

只修复 Bug、显示宠物、加少量按钮和样式。优点是快；缺点是无法满足「一系列养成系统」和「能打发时间」。

### 方案 C：完整电子宠物版

在方案 A 上继续增加房间装饰、道具树、性格成长、更多小游戏。优点是上限最高；缺点是明显超出本次插件打磨范围，风险与测试成本过高。

## 6. 核心循环

```text
用户正常使用网关
  → 插件自动把成功请求的 tokens 喂给当前搭档
  → 宠物成长、产生状态变化与每日目标进度
  → 用户花 1–3 分钟照顾或派出探险
  → 获得亲密、碎片、图鉴/成就反馈
  → 回到自动成长与进化收集
```

设计原则：token 仍是主成长来源；主动照顾提供陪伴感和短期反馈，但不替代进化槽，也不消耗用户 token。

## 7. 养成规则

### 7.1 状态

每个搭档各拥有一组 0–100 的状态，状态以 `partner_id` 为主键长期保留。孵新蛋会创建新搭档的初始状态；同一搭档进化只更换 sprite，不重置状态；冻结、退役或之后切回旧搭档时，其照顾状态与亲密仍保留：

| 状态 | 含义 | 主要来源 | 随时间变化 |
|---|---|---|---|
| 饱食 | 是否饿着 | 自动 token 进食、点心 | 缓慢下降 |
| 心情 | 是否开心 | 玩耍、探险成功 | 缓慢下降 |
| 精力 | 是否能行动 | 休息、自然恢复 | 玩耍/探险消耗 |
| 清洁 | 是否需要清理 | 清洁操作 | 缓慢下降 |
| 亲密 | 陪伴程度 | 抚摸、玩耍、探险 | 不随时间惩罚 |

状态衰减要「温和且可恢复」：离线衰减按经过时间计算，但最多累计 24 小时；低状态只影响动画、文案和探险收益，不阻止进化，不导致死亡。

### 7.2 主动操作

| 操作 | 效果 | 限制 |
|---|---|---|
| 喂食点心 | 饱食增加，少量心情增加 | 短冷却，避免连点刷满 |
| 玩耍 | 心情与亲密增加，消耗精力 | 需要最低精力，有冷却 |
| 清洁 | 清洁恢复到高位 | 有冷却，清洁较低时额外奖励亲密 |
| 休息 | 精力恢复 | 有冷却；冻结中也可休息 |
| 摸蛋 | 蛋阶段获得亲密与孵化反馈 | 仅蛋阶段显示，短冷却 |

所有操作都立即给出动画与文案反馈；失败原因也必须明确，例如「它现在太困了，先休息一下」。

### 7.3 探险

- 同一时刻最多一场探险。
- 首版提供 3 个时长档位：短巡逻、数据原野、深夜远征。
- 探险使用本地计时器，可关闭页面后回来结算。
- 结算奖励：数据碎片、亲密、一条见闻文本；根据宠物状态和时长调整奖励，但不设置失败惩罚。
- 数据碎片是本地收藏货币，用于解锁主题背景、边框、称号等纯装饰内容；首版至少提供 3 个可解锁项。

### 7.4 每日目标与成就

每日目标只使用本地日期，不依赖云时间：

- 照顾宠物 2 次。
- 完成 1 次探险。
- 今天累计自动进食若干请求。

目标奖励少量数据碎片或亲密。成就首版包含：首次抚摸、首次清洁、首次探险、累计照顾 10 次、累计获得 100 碎片、完成一次进化。

## 8. 界面与视觉

### 8.1 页面结构

首屏改为四层：

1. **宠物栖息地**：占首屏核心位置，显示像素宠物、背景、状态动画和一句拟人化状态。
2. **状态条**：饱食、心情、精力、清洁、亲密，以及原有进化进度。
3. **行动区**：喂食、玩耍、清洁、休息、摸蛋、探险，按钮显示冷却或不可用原因。
4. **收集与记录**：每日目标、碎片与装饰、图鉴完成度、世代列表、喂食流水。

设置、冻结、孵新蛋和钉 ID 保留，但放入「管理」区域，不与日常照顾按钮抢视觉焦点。

### 8.2 宠物渲染

- 从本机已有的 Apache-2.0 上游打包产物中提取像素帧目录，生成插件自己持有的静态 `monster-frames.json`。
- 页面用 Canvas 或 DOM 像素网格渲染，不使用远程图片。
- 支持上游已有姿态：待机、行走、进食、开心、生气、受伤、拒绝、睡觉；缺失姿态时回退到行走/待机。
- 根据当前 `sprite` ID 精确取帧；若某只没有对应帧，则按 ID 与阶段生成稳定的像素兜底形象，避免空白。
- 栖息地包含前景地面、背景粒子、昼夜/主题色，不做性能敏感的大型场景。

### 8.3 视觉约束

- 同时支持浅色与深色主题；默认跟随 Magpie 传入的 `theme` 参数。
- 主要按钮、状态值和警示文字对比度可读。
- 1440px 桌面和较窄侧边栏都能使用；关键操作不依赖悬停。
- 动画以低帧率像素动画为主，避免持续重绘整页。

## 9. 技术方案

### 9.1 边界

上游 token 进化引擎继续由 `lib/upstream/index.js` 与 `pet.adapter.mjs` 驱动。新养成层不修改上游表含义，不改进化路线，不直接绕过引擎写 `partners`、`usage_receipts` 等既有表。

新增模块建议：

- `lib/pet.care-rules.mjs`：纯规则，计算衰减、操作结果、探险结算和成就。
- `lib/pet.care-store.mjs`：SQLite 迁移与读写，只管理新表。
- `lib/pet.frames.mjs`：加载像素帧并提供兜底。
- `page/app.css`、`page/app.js`：把当前单文件页面拆成结构、样式、行为，便于测试与维护。
- `tools/extract-frames.mjs`：从上游 bundle 生成 `lib/monster-frames.json`，生成物纳入版本控制。

### 9.2 新增数据表

表名统一使用 `magpie_pet_` 前缀，避免与上游表冲突：

- `magpie_pet_care_state`：活跃搭档的五项状态、冷却、更新时间。
- `magpie_pet_care_events`：照顾、探险、成就事件，用于页面记录和调试。
- `magpie_pet_expeditions`：探险状态、开始/结束时间、结算结果。
- `magpie_pet_inventory`：碎片与已解锁装饰。
- `magpie_pet_achievements`：本地成就完成时间。
- `magpie_pet_daily`：本地日期、目标进度与奖励领取状态。

迁移必须幂等，现有 `pet.db` 打开后自动升级；当前第 1 代 Digiegg 的进度不得丢失。

### 9.3 API 与命令

`/api/state` 返回合并后的只读快照：上游伙伴状态 + 新养成状态 + 当前探险 + 目标/成就摘要。`/api/command` 继续只允许白名单命令，新增：

- `pet-feed-snack`
- `pet-play`
- `pet-clean`
- `pet-rest`
- `pet-pet-egg`
- `pet-expedition-start`
- `pet-expedition-claim`
- `pet-decoration-equip`

所有命令服务端校验冷却、活跃搭档、探险状态与参数范围；页面禁用状态只作为体验优化，不作为安全边界。本轮 CLI 不要求与页面操作对等：保留 `status | spawn | freeze | unfreeze | set | events | partners`，只让 `status` 额外显示当前搭档的五项状态、碎片和进行中探险；完整照顾与探险入口在页面。

### 9.4 明确修复

1. **服务关闭测试误判**：自检不能使用「fetch 是否 resolve」判断 127.0.0.1 服务是否关闭；改为不经过系统代理的 Node `http` 请求，或明确要求关闭后不再返回 `/api/ping` 的 HTTP 200。可选增强是让 `close()` 主动销毁活动 socket，但不得把代理 502 当成服务未关闭。
2. **设置页数据库路径**：改为实际默认路径 `<插件目录>\data\pet.db`，并说明可用 `dbPath` 覆盖。
3. **HTML 输出安全**：所有宠物名、事件、错误文案用 DOM API 或转义后渲染，不直接把接口字段拼进 `innerHTML`。
4. **静态路径处理**：使用规范化绝对路径，并确认最终路径严格位于 `page/` 目录内。
5. **README/CLI/页面口径**：统一数据库路径、功能说明和操作入口。

## 11. 交给实施者判断的内容

- 具体配色、背景形状、文案语气和装饰名称。
- 状态衰减与冷却的最终数值，只要符合「低压力、几分钟可完成」原则。
- Canvas 或 DOM 像素网格的取舍，以渲染清晰与测试方便为准。
- 动画帧率、文件拆分粒度和纯函数命名。

## 12. 当前假设

- 用户选择路线 1，并更重视「数码宝贝进化与收集」，同时希望有日常照顾陪伴感。
- 本地单机是正确边界；没有引入云服务的必要。
- 上游内嵌像素帧可在 Apache-2.0 许可下继续随移植包使用，保留 NOTICE。
- 进化对决的完整 UI 不作为第一版阻断项；先显示并优化现有待战状态，待实现层确认上游内部能力暴露方式后再决定是否接入可点击对决。
